# ArmDemo Engineering Log — 2026.9.14

## English

### Goals

- Refactor the IO layer onto the standard AdvantageKit pattern: a top-level `ArmIO`/`ElevatorIO` contract with an `updateInputs(inputs)` poll and an `@AutoLog` inputs container, so sensor values are read once per cycle, logged wholesale, and replayable.
- Move the NetworkTables tuning entries out of `RobotContainer` into the subsystems that own them, and poll them once per `periodic()` — the same once-per-cycle pattern as the sensor inputs (the 6328-style tuning pattern).
- Zero behavior change: same limits, same voltages, same telemetry keys, all 53 tests passing unchanged.

### Completed Work

- Added the `akit-autolog` annotation processor to `build.gradle` and registered the generated-sources directory, so `@AutoLog` containers get their `*AutoLogged` replay classes.
- Created top-level `ArmIO` and `ElevatorIO` interfaces: each declares `updateInputs(inputs)` (the single sensor read per cycle), the output setters, and an `@AutoLog` inputs container (rotations, applied volts). The old `ArmEncoderPositions`/`ElevatorEncoderPositions` records and the interfaces nested inside the subsystems were removed.
- Rewrote the three IO implementations around `updateInputs`: the TalonFX implementations refresh all their status signals in one `BaseStatusSignal.refreshAll` transaction and also report the last applied voltage back through the inputs; `ArmIOThroughBore` fills the same container from the absolute encoder and remains a drop-in switch.
- `ArmSubsystem` and `ElevatorSubsystem` now hold an `*AutoLogged inputs` field: `periodic()` runs in a fixed order — poll tuning entries (sanitized once per cycle), `io.updateInputs(inputs)`, `Logger.processInputs(...)`, then all control logic reads the snapshots. All control behavior (limits, taper, slew, speed cap, hold zones, interlock, timing) is unchanged; the AdvantageScope telemetry keys are unchanged.
- The six NetworkTables tuning entries moved from `RobotContainer` into the subsystems that consume them. Production constructors create their own `LoggedNetworkNumber`s (same keys, same defaults); the old supplier-taking constructors remain as package-private test seams so every existing test injects constants exactly as before.
- Slimmed `RobotContainer` to wiring only: the through-bore switch, the two subsystem constructions (3 and 2 arguments instead of 10 and 4), the arm→elevator interlock connection, and the button bindings. Six `LoggedNetworkNumber` fields and their imports are gone.
- Updated both test `Fake` IO classes to implement `updateInputs` with plain fields; no assertion changed. One elevator test (direction-reversal ramp) now calls `periodic()` after changing its injected slew value, because tuning values are polled once per cycle by design — the test now documents that behavior.
- One build fix along the way: the `@AutoLog` processor generates top-level `ArmIOInputsAutoLogged`/`ElevatorIOInputsAutoLogged` classes, not nested ones — our first references used the wrong qualification.
- 53 tests green, full build passes.

### Why It Matters

- Sensor reads are now structurally impossible to skip or double-read: one method, one call site, one batched CAN transaction per cycle.
- Tuning values behave the same way: polled once per cycle into sanitized snapshots, so a dashboard edit mid-cycle can never tear a decision across two values, and invalid values are rejected in exactly one place.
- The inputs containers are logged through `Logger.processInputs`, which is the foundation for AdvantageKit log replay: a match log can later be fed back through the same code offline.
- `RobotContainer` now reads as a one-page wiring diagram; each subsystem is self-contained and lists its own tuning knobs.

### Next Steps

- On-robot: verify buttons 5/6 mapping and first action-timing records (unchanged from 9.5).
- Optional follow-up: adopt a `LoggedTunableNumber`-style `hasChanged` wrapper on top of the polling pattern when a controller actually needs change-triggered reconfiguration.

## 中文

### 今日目标

- 把 IO 层重构到标准 AdvantageKit 模式：顶层 `ArmIO`/`ElevatorIO` 契约 + `updateInputs(inputs)` 每周期一次的轮询 + `@AutoLog` 输入容器，使传感器值每周期只读一次、整体入日志、可回放。
- 把 NetworkTables 调参项从 `RobotContainer` 移进拥有它们的子系统，并在 `periodic()` 里每周期轮询一次——与传感器输入相同的"每周期一次"模式（6328 式调参模式）。
- 行为零变化：限位、电压、遥测键名全部不变，53 个测试原样通过。

### 已完成工作

- 在 `build.gradle` 加入 `akit-autolog` 注解处理器并注册生成源目录，使 `@AutoLog` 容器生成对应的 `*AutoLogged` 回放类。
- 新建顶层 `ArmIO` 与 `ElevatorIO` 接口：各自声明 `updateInputs(inputs)`（每周期唯一的传感器读取入口）、输出方法，以及 `@AutoLog` 输入容器（编码器圈数、已输出电压）。原先嵌在子系统里的接口和 `ArmEncoderPositions`/`ElevatorEncoderPositions` record 已删除。
- 按新契约重写三个 IO 实现：两个 TalonFX 实现用一次 `BaseStatusSignal.refreshAll` 事务刷新全部状态信号，并把最近输出电压通过 inputs 回报；`ArmIOThroughBore` 用绝对编码器填充同一容器，仍然是一行开关即可切换的即插即用实现。
- `ArmSubsystem` 和 `ElevatorSubsystem` 现在持有 `*AutoLogged inputs` 字段：`periodic()` 按固定顺序执行——轮询调参项（每周期消毒一次）→ `io.updateInputs(inputs)` → `Logger.processInputs(...)` → 全部控制逻辑读取快照。所有控制行为（限位、渐变减速、斜坡、速度帽、保持分区、联锁、计时）不变；AdvantageScope 遥测键名不变。
- 六个 NetworkTables 调参项从 `RobotContainer` 移入消费它们的子系统。生产构造器自己创建 `LoggedNetworkNumber`（键名、默认值不变）；原来带 supplier 的构造器保留为包内可见的测试通道，所有既有测试照旧注入常量。
- `RobotContainer` 瘦身为纯接线：through-bore 开关、两个子系统构造（从 10/4 参数缩到 3/2 参数）、机械臂→Elevator 联锁连接、按键绑定。六个 `LoggedNetworkNumber` 字段及其导入全部删除。
- 两个测试 `Fake` IO 改为实现 `updateInputs`（普通字段填充）；断言一条没改。电梯"方向反转斜坡"测试在修改注入的斜坡值后补了一次 `periodic()`——因为调参值按设计每周期轮询一次，测试现在把这一行为固化成了文档。
- 过程中修了一个构建问题：`@AutoLog` 处理器生成的是**包级顶层类** `ArmIOInputsAutoLogged`/`ElevatorIOInputsAutoLogged`，而不是嵌套类——最初的引用写错了限定名。
- 53 个测试全绿，整包构建通过。

### 为什么这样做

- 传感器读取在结构上不可能被跳过或重复：一个方法、一个调用点、每周期一次批量 CAN 事务。
- 调参值同样每周期轮询进消毒快照：调参手在周期中途改值不可能让一次决策撕裂在两个值上，非法值只在唯一一处被拒绝。
- inputs 容器通过 `Logger.processInputs` 整体记录，这是 AdvantageKit 日志回放的基础：比赛日志之后可以离线喂回同一份代码重放。
- `RobotContainer` 现在就是一页接线图；每个子系统自成一体，自己的旋钮自己声明。

### 后续计划

- 上机：验证按键 5/6 映射与第一批动作计时记录（与 9.5 相同的待办）。
- 可选跟进：当某个控制器真正需要"值变了才重配置"时，在轮询模式上加一层 `LoggedTunableNumber` 式的 `hasChanged` 包装。
